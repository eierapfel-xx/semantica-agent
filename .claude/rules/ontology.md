# オントロジーを書くときの決まり

- ファイルは Turtle（`.ttl`）で `ontology/` に置き、スキーマ（クラス・プロパティ）、SHACL シェイプ、インスタンスを別ファイルに分ける。ファイル名と分け方は仕様書で決める。
- クラス・プロパティの IRI のローカル名は英語（クラスは UpperCamelCase、プロパティは lowerCamelCase）。日本語名は `rdfs:label "…"@ja` に、説明は `rdfs:comment "…"@ja` に書く。
- 名前空間の URI はコードの 1 か所（定数）で定義し、Turtle の `@prefix` と一致させる。
- 手順書から起こしたインスタンスには出典（業務名・区分・ページ）を持たせる。根拠法令（「戸籍法第49条」など）は文字列でなく法令のノードとして表し、手順・審査項目から参照する。
- 手順書に書かれていないことを推測で足さない。足すときは出典の代わりに「推測」と分かる注記を付け、仕様書に理由を書く。
- オントロジーを変えたら、SHACL 検証と competency questions の SPARQL テストを流す。
- オントロジーは LLM（`LLMOntologyGenerator` ＋ Agent SDK のプロバイダー）で生成し、生成物は人が差分を読める Turtle で保存する。生成のたびに、使ったプロンプト・モデル・入力のページをメタデータに残す。
- LLM の生成結果を手で直したときは、直したことと理由が分かるように残す（コミットを分ける等）。
